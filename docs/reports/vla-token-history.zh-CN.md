## 保留的归属与范围说明

- 原生计数来自 OpenCode 2.2.7 assistant／compaction 的 usage 字段；模型归属是
  任务活动估算。专属子会话优先按任务标题；主会话优先按单模型工具输入，再看当前
  主题。共有、混合、压缩及公共协调不按模型数、代码量或延迟比例分摊。
  通用安装目录、被参考的另一模型源码以及共用 allocation 路径不视为专项归属。
  父代理工具回执转述的子代理 token 不再次计入。
- 11-15 范围为主会话加 69 个直接子会话，共 70 个；无 fork 或重复消息计数，
  排除旧父会话的两个子会话，包含九条主会话 compaction。10 月移植、
  真机部署、训练、下载等其他根任务不属于这批统计，不能解释成零成本。
- 三份 11-16 新增窗口分别覆盖 6／7／8 个会话，与旧窗口仅主会话重合，
  合并范围分别为 75／76／77 个。初次快照排除刚开始的 DM0.5 项目／FlashRT
  补接入；第二份包含补接入与正式计时；第三份再包含编译优化及配对计时、
  截点前协调与报告。每份均排除截点后的当前整理。
- 第二份有一条截点前创建的消息在取数时尚未结束，结束后读取真实 usage，
  截点保持不变。第三份在最近完成 provider step 的创建时间后 1 ms 截断，
  排除仍运行的消息。各增量最终无缺失；旧 14 条缺失（Hy 3、shared 11）
  始终保持未知，不能以 cache-write 为 0 推断缺失消息无消耗。
- DM0.5 第二份比初次快照增加 33,316,835 总处理／512,483 非缓存；
  第三份比第二份增加 28,289,341／1,667,773。这是活动归属差额，不能称为
  独立“纯编码成本”，也不能对同模型的多个后端／延迟测量点重复累计。
- 11-15 的 `stages` 是工作阶段，保留原名和计数，不冒充流水线 stage ID。
  `initial_adaptation` 的公共时间代理为 2026-11-08T14:20:41.449Z 至
  2026-11-09T09:56:32.719Z，不是各模型完成验收时间。四模型该阶段原值为
  pi0 16,849,618、pi05 33,433,601、FastWAM 32,129,035、Hy 17,007,184，
  shared 111,211,028；合计 210,630,466。Hy 后续排查 740,401,955
  （12,511,011 非缓存＋727,890,944 cache-read）仍是历史排查投入。
  DM0.5 没有历史接入阶段分解，现行四表保持 unknown。
- 原取数报告没有执行模型、测试或额外评审，没有读写会话数据库；本次封装的 CPU

## 复现输入与原始文件恢复

从历史包独立生成只有冻结历史的四张表（无需 Torch／GPU）：

```bash
python -m flash_rt.vla.autotune.token_usage report \
  --history docs/reports/vla-token-history.json \
  --segments devlocal/h-history/empty-segments.jsonl \
  --run-start 2026-11-24T02:21:18.867Z \
  --cutoff 2026-11-24T03:57:08.343866Z \
  --output devlocal/h-history/frozen-history
```

这里 `empty-segments.jsonl` 应不存在或为空；输出总处理仍为 1,741,698,368，
四表中的历史阶段和缺失数可独立复算。要复现 H 的 03:57 原发布四表，使用当时
已有的私有原生聚合投影（不公开逐消息文件），固定相同截点：

```bash
python -m flash_rt.vla.autotune.token_usage report \
  --records devlocal/platform/token-usage-native.jsonl \
  --segments docs/vla_autotune_token_segments.jsonl \
  --history docs/reports/vla-token-history.json \
  --run-start 2026-11-24T02:21:18.867Z \
  --cutoff 2026-11-24T03:57:08.343866Z \
  --output devlocal/h-history/reproduced \
  --require-attribution
```

原生投影的收集摘要固定 1,400 条、23 条 usage 缺失；SHA-256 为
`d36a8fc2c533813c758560b7060a962de6fee1782d4aafed985f29a195c15465`。
此命令复算同一窗口，不移动当前报告截点，也不重新读取正在结算的消息。
复现 H 输出需要拥有该私有投影；公开包独立支持原历史数值与四表复算，
不把私有逐消息数据的未公开伪装成公开全量复现。

九个撤下入口逐项列于[清理映射](../vla_autotune_cleanup.zh-CN.md#h-history-retention)，
`archived_artifacts` 保留每个原路径、字节数和 SHA-256。取回任何一个原文的方式：

```bash
git show 199376281801427abccbb307056b27e74eab1429:docs/reports/2026-11-16-vla-development-token-usage-dm05-optimized.json
git show 199376281801427abccbb307056b27e74eab1429:docs/reports/2026-11-16-vla-development-token-usage-post-dm05.zh-CN.md
```

无需 Git 的 JSON 恢复也可从 `snapshots` 选择原 `source`，按包内
`snapshot_encoding` 序列化 `data`；重建 CSV 时按 `models` 的原始顺序输出
`model,input,output,reasoning,cache_read,cache_write,uncached_work_tokens,all_processed_tokens,usage_records,missing_usage_records`，
使用 UTF-8 和 LF 换行。CPU 回归实际校验三份 JSON／CSV 的原始摘要，
不是只比较总量。
